# Reference results (paper numbers)

Machine-readable reference values for every synthetic and FUSS number in the paper
*When Attention Collapses: Residual Evidence Modeling for Compositional Inference*
(NeurIPS 2026). Table, figure and appendix numbers refer to the camera-ready version.
LISA results are not part of this release. How to regenerate each number is described
in [`docs/reproduce.md`](../../docs/reproduce.md).

## Files

| File | Paper artifact |
|---|---|
| `synthetic_main.json` | Table 1 (synthetic columns), Figure 1 (synthetic groups), Table 9 (App. G), Table 8 (App. F, synthetic columns) |
| `alternatives.json` | Table 2 and the cosine statements of Sec. 3.1 / App. H |
| `loss_baselines.json` | Table 10 (App. H) and the "Loss-based regularization" paragraph of Sec. 3.1 |
| `sensitivity.json` | Table 7 (App. E, γ × τ) |
| `stress.json` | App. I: Table 11 (amplitude ratio), slot over-provisioning, cardinality, token count, early errors and slot order, Table 12 (latency) |
| `fuss.json` | Table 1 FUSS column, Table 13, Table 8 FUSS column, SI-SDR diagnostics, oracle mask, parameter baseline (App. J) |
| `app_d_readout_check.json` | App. D empirical readout check (κ, ρ, readout cosines) |
| `raw/` | The original per-run result files (see below) |

Each table cell has this layout:

```json
{"task": "sinusoids", "method": "evidence_linear", "metric": "peak_overlap",
 "paper": {"mean": 0.07, "std": 0.07},
 "per_seed": {"0": 0.0202, "1": 0.0075, "2": 0.0764, "3": 0.1967, "4": 0.043},
 "recomputed": {"n": 5, "mean": 0.06876, "std_pop": 0.06812, "std_sample": 0.07616},
 "check": {"mean_ok": true, "std_pop_ok": true, "std_sample_ok": true, "at_rounding_boundary": []},
 "provenance": "per_seed_file", "source": "raw/synthetic_main_ablation_results.json"}
```

`paper` holds the value printed in the paper. `recomputed` is computed from
`per_seed`. `check` says whether the paper value equals the recomputed value rounded
to two decimals; `at_rounding_boundary` lists the quantities that lie within 0.0006 of
a rounding boundary.

Metric names map to the JSON fields that the experiment scripts write: `peak_overlap`
is `collapse_rate`, and `cosine_overlap` is `mean_attn_overlap`.

## Aggregation convention

The paper reports the mean and the **population** standard deviation (`numpy.std`,
ddof = 0) over seeds 0, …, N−1. All cells of Tables 1, 7, 9, 10, 11 and 13 reproduce this
way, as do all cells of Table 2. A sample std (ddof = 1) would change several
other cells; for example, vanilla on sinusoids would become 0.10.

## Provenance levels

| `provenance` | Meaning |
|---|---|
| `per_seed_file` | Per-seed values from the original result files. A copy is in `raw/`. |
| `run_log` | Per-seed values from the original training logs, which print three decimals; one record per printed run line in `raw/log_records.json`. Logs of the method comparisons do not print the cosine overlap; amplitude-ratio runs print both metrics. |
| `reported_only` | Summary value as reported in the paper; per-seed files not retained. It can only be regenerated by re-running the experiment. |
| `recomputed` | Recomputed with the released code (App. D κ check). |

## `raw/` contents

All files use the original schemas of the experiment scripts and contain no paths or
user names. `python scripts/make_tables.py results/paper/raw` turns them back into the
paper tables.

| File | Content |
|---|---|
| `synthetic_main_ablation_results.json` | 200-epoch synthetic sweep: 8 methods × 3 tasks × 5 seeds. Peak overlap only (written before the cosine metric was added). |
| `loss_baselines_baseline_results.json` | Loss-based baselines: 6 variants × 3 tasks × 5 seeds. |
| `sensitivity_ablation_results.json` | γ × τ grid, sinusoids, 3 seeds. |
| `mesh_full_ablation_results.json` | Full MESH, 3 tasks × 5 seeds, including `mean_attn_overlap`. |
| `fuss_v2_fuss_results.json` | The earlier FUSS run reported in the submitted version (not in the camera-ready tables), made with a previous version of the FUSS script (no cosine or SI-SDR fields). |
| `order_studies_results.json` | Early-error and slot-order studies (App. I). |
| `latency_results.json` | Latency microbenchmark, CPU and GH200 (Table 12). |
| `app_d_readout_trained_results.json` | App. D readout geometry on trained checkpoints (its `bound` field is 1−2ρ², which App. D shows is not a valid bound; kept for reference). |
| `log_records.json` | Every per-run line parsed from the original training logs: synthetic method comparisons (alternatives, full MESH, a rerun of the main sweep), amplitude ratio, slot stress, token count and FUSS. Each record has a `source` label naming its run group (e.g. `alternatives/part_a`, `fuss_rerun/vanilla`); duplicates from interrupted and resumed runs are kept. In these records `sa_sh` is the method that the original logs print as `mesh`; `mesh` (source `mesh_full`) is full MESH. |
